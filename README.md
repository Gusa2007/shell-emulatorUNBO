# Эмулятор командной оболочки (вариант 3)

GUI-эмулятор языка оболочки UNIX-подобной ОС на Python (tkinter).
Работа эмулятора максимально похожа на работу в терминале: приглашение
`user@host:/$`, история ввода стрелками, сообщения об ошибках в стиле bash.

## Этап 1. REPL

* окно на tkinter, заголовок строится из данных реальной ОС:
  `Эмулятор - [username@hostname]`;
* парсер командной строки с поддержкой кавычек `'...'`, `"..."`
  и экранирования `\`;
* сообщения об ошибках: неизвестная команда, неверные аргументы,
  незакрытая кавычка;
* команды-заглушки `ls`, `cd` (выводят имя и аргументы);
* команда `exit [код]`.

## Этап 2. Конфигурация

Параметры командной строки:

| Параметр        | Назначение                                   |
|-----------------|----------------------------------------------|
| `--vfs PATH`    | путь к физическому расположению VFS          |
| `--script PATH` | путь к стартовому скрипту команд эмулятора   |
| `-h, --help`    | справка по параметрам                        |

При запуске в окно выводятся (серым) значения всех параметров:

```
[debug] vfs_path    = 'vfs.zip'
[debug] script_path = 'examples/stage2.emu'
```

Стартовый скрипт -- текстовый файл с командами эмулятора, по одной
в строке. Комментарии -- как в Python: `#` в начале слова (вне кавычек)
и до конца строки. Пустые строки пропускаются. При выполнении на экране
показываются и ввод (приглашение + команда), и вывод. После ошибки
выполнение продолжается, в конце выводится число строк с ошибками;
команда `exit` прекращает скрипт.

Скрипты ОС для проверки всех параметров -- `scripts/stage2_*.sh`.

## Этап 3. VFS

* источник VFS -- ZIP-архив (`--vfs PATH`); архив только читается,
  всё дерево хранится в памяти и изменяется только там;
* содержимое файлов хранится байтами, двоичные данные при выводе
  представляются в base64;
* если в корне VFS есть файл `motd`, его текст выводится при старте;
* ошибки загрузки (нет файла, не ZIP-архив, недопустимые пути `..`)
  сообщаются, эмулятор продолжает работу с пустой VFS.

Архивы в репозитории не хранятся. Исходные данные лежат в каталоге
`vfs/`, архивы собираются командой `make vfs`
(или `python3 tools/make_vfs.py`) в `build/vfs/`:

| VFS         | Содержимое                                          |
|-------------|-----------------------------------------------------|
| `minimal`   | только `motd`                                       |
| `few_files` | несколько файлов, скрытый файл, двоичный `logo.png` |
| `deep`      | дерево до 5 уровней, пустые каталоги, пробелы в именах |

Соглашения сборщика: `.keep` сохраняет в git пустой каталог и
в архив не попадает; `имя.b64` декодируется из base64 в двоичный
файл `имя`.

Скрипты ОС: `scripts/stage3_*.sh` (разные VFS и ошибки загрузки),
стартовый скрипт: `examples/stage3.emu`.

## Структура

```
src/main.py              точка входа
src/emulator/parser.py   разбор строки на слова
src/emulator/shell.py    ядро: выполнение команд
src/emulator/commands.py встроенные команды
src/emulator/gui.py      окно терминала
src/emulator/system.py   данные реальной ОС
src/emulator/config.py   параметры командной строки
src/emulator/vfs.py      VFS в памяти, загрузка из ZIP
tools/make_vfs.py        сборка ZIP-архивов VFS из vfs/
vfs/                     исходные данные для VFS
examples/                стартовые скрипты эмулятора (*.emu)
scripts/                 скрипты ОС для демонстрации этапов
tests/                   тесты pytest
```

## Запуск и тесты

Требуется Python 3.8+ с tkinter.

```sh
make vfs                                             # собрать VFS
./run.sh --vfs build/vfs/deep.zip --script examples/stage2.emu   # Linux / macOS
run.bat --script examples\stage2.emu                  # Windows
make test         # тесты (нужен pytest)
make lint         # проверка стиля (нужен flake8)
```

## Пример

```
user@host:/$ ls -l "My Documents"
ls: аргументы ['-l', 'My Documents']
user@host:/$ cd a b
cd: слишком много аргументов
user@host:/$ foo
emu: foo: команда не найдена
user@host:/$ ls "abc
emu: синтаксическая ошибка: незакрытая двойная кавычка
```
