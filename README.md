# Эмулятор командной оболочки (вариант 3)

GUI-эмулятор языка оболочки UNIX-подобной ОС на Python (tkinter).
Работа эмулятора максимально похожа на работу в терминале: приглашение
`user@host:/путь$`, история команд, сообщения об ошибках в стиле bash.
Файловая система -- виртуальная (VFS): загружается из ZIP-архива и
живёт только в памяти, исходный архив никогда не изменяется.

## Возможности

* окно на tkinter, заголовок из данных реальной ОС:
  `Эмулятор - [username@hostname]`;
* парсер командной строки: кавычки `'...'` и `"..."`, экранирование `\`,
  склейка частей слова, комментарии `#`;
* параметры запуска `--vfs` и `--script`, отладочный вывод параметров;
* стартовый скрипт: команды выполняются с показом ввода и вывода;
* VFS из ZIP-архива в памяти, двоичные данные -- в base64, `motd`;
* команды `ls`, `cd`, `who`, `history`, `rmdir`, `help`, `exit`.

## Требования и запуск

Нужен Python 3.8+ с tkinter (в Windows и macOS входит в установщик
python.org; в Debian/Ubuntu -- пакет `python3-tk`). Для тестов --
`pytest`, для проверки стиля -- `flake8`.

```sh
make vfs                                    # собрать архивы VFS
./run.sh --vfs build/vfs/deep.zip           # Linux / macOS
run.bat --vfs build\vfs\deep.zip            # Windows
make run                                    # то же через make
make test                                   # запуск тестов
make lint                                   # проверка стиля
sh scripts/run_all.sh                       # демонстрация всех этапов
```

Без `make`: `python3 tools/make_vfs.py`, `python3 src/main.py [...]`,
`python3 -m pytest`.

## Параметры командной строки

| Параметр        | Назначение                                        |
|-----------------|---------------------------------------------------|
| `--vfs PATH`    | путь к ZIP-архиву с VFS (без него VFS пуста)      |
| `--script PATH` | стартовый скрипт с командами эмулятора            |
| `-h, --help`    | справка по параметрам                             |

При запуске в окно выводятся (серым) значения всех параметров и
статистика загруженной VFS, затем текст `/motd` (если есть), затем
выполняется стартовый скрипт:

```
[debug] vfs_path    = 'build/vfs/deep.zip'
[debug] script_path = 'examples/stage5.emu'
[debug] VFS загружена из build/vfs/deep.zip: каталогов 17, файлов 10
```

## Команды

* `ls [-l] [-a] [путь...]` -- содержимое каталога. Без аргументов --
  текущий каталог; `-a` -- скрытые файлы, `.` и `..`; `-l` -- права,
  число ссылок, владелец, размер, дата; ключи объединяются (`-la`);
  несколько путей выводятся с заголовками; имена с пробелами -- в кавычках.
* `cd [путь | - | ~]` -- смена каталога: абсолютные и относительные пути,
  `.` и `..`; без аргументов и `~` -- домашний каталог `/`;
  `-` -- предыдущий каталог.
* `who [-H] [-q] [am i]` -- пользователь ОС, терминал, время начала
  сеанса; `-H` -- с заголовком; `-q` -- имена и число пользователей.
* `history [-c] [N]` -- нумерованная история; `N` -- последние N команд;
  `-c` -- очистить историю.
* `rmdir [-p] каталог...` -- удалить пустые каталоги (только в памяти);
  `-p` -- также родителей, ставших пустыми.
* `help [команда]` -- список команд с описанием или справка по одной.
* `exit [код]` -- завершить работу и закрыть окно.

Ключ `--` завершает список ключей. Сообщения об ошибках:
`команда не найдена`, `синтаксическая ошибка: незакрытая кавычка`,
`Нет такого файла или каталога`, `Это не каталог`, `Каталог не пуст`,
`Устройство или ресурс занято` (удаление текущего каталога или его
предка), `неверный ключ`, `лишний операнд`, `пропущен операнд`,
`требуется числовой аргумент`, `слишком много аргументов`.

В строке ввода стрелки вверх/вниз листают историю. В историю попадают
команды, введённые вручную и выполненные из стартового скрипта
(пустые строки и строки из одного комментария не попадают).

## Стартовый скрипт

Текстовый файл (UTF-8) с командами эмулятора, по одной в строке.
Комментарии -- как в Python: `#` в начале слова вне кавычек и до конца
строки (`a#b` и `"#x"` -- обычные аргументы). Пустые строки
пропускаются. На экране показываются приглашение с командой и её
вывод, как при ручном вводе. После ошибки выполнение продолжается,
в конце выводится число строк с ошибками; `exit` прекращает скрипт.

## VFS

* источник -- ZIP-архив, он только читается; всё дерево (`Directory`,
  `File`) хранится в памяти, `rmdir` меняет только его;
* содержимое файлов хранится байтами, двоичные данные при выводе
  представляются в base64;
* поддерживаются явные записи каталогов (пустые каталоги) и неявные
  (по путям файлов); пути с `..` отвергаются;
* ошибки загрузки (нет файла, не ZIP-архив) сообщаются, эмулятор
  продолжает работу с пустой VFS.

Архивы в репозитории не хранятся: исходные данные лежат в `vfs/`,
архивы собирает `tools/make_vfs.py` в `build/vfs/`. Соглашения:
`.keep` сохраняет в git пустой каталог и в архив не попадает;
`имя.b64` декодируется из base64 в двоичный файл `имя`.

| VFS         | Содержимое                                             |
|-------------|--------------------------------------------------------|
| `minimal`   | только `motd`                                          |
| `few_files` | несколько файлов, скрытый файл, двоичный `logo.png`    |
| `deep`      | дерево до 5 уровней, пустые каталоги, пробелы в именах |

## Демонстрация по этапам

| Этап | Скрипты ОС (`scripts/`) | Стартовый скрипт (`examples/`) |
|------|-------------------------|--------------------------------|
| 1. REPL | интерактивный режим: `./run.sh` | -- |
| 2. Конфигурация | `stage2_*.sh` -- все сочетания параметров, ошибки | `stage2.emu` |
| 3. VFS | `stage3_*.sh` -- разные VFS и ошибки загрузки | `stage3.emu` |
| 4. Основные команды | `stage4_commands.sh` | `stage4.emu` |
| 5. Дополнительные команды | `stage5_commands.sh` | `stage5.emu` |

## Структура

```
src/main.py                    точка входа
src/emulator/parser.py         разбор строки на слова
src/emulator/shell.py          ядро: выполнение команд, скрипты, VFS
src/emulator/commands/         встроенные команды
    registry.py                реестр команд, разбор ключей
    fs.py                      ls, cd, rmdir
    session.py                 exit, who, history, help
src/emulator/vfs.py            VFS в памяти, загрузка из ZIP
src/emulator/config.py         параметры командной строки
src/emulator/gui.py            окно терминала (tkinter)
src/emulator/system.py         данные реальной ОС
tools/make_vfs.py              сборка ZIP-архивов VFS
vfs/                           исходные данные для VFS
examples/                      стартовые скрипты эмулятора (*.emu)
scripts/                       скрипты ОС для демонстрации этапов
tests/                         тесты pytest
```

Ядро (`Shell`) не зависит от GUI: весь вывод идёт через функцию
`output(text, kind)`, поэтому команды тестируются без окна.

## Примеры использования

```
root@vm:/$ ls -a /home/user
.  ..  .profile  'My Documents'  docs
root@vm:/$ cd "/home/user/My Documents"

/home/user
root@vm:/home/user$ ls -l docs

root@vm:/home/user$ rmdir docs

root@vm:/home/user$ who -H

    7  history 2

root@vm:/home/user$ ls "abc
emu: синтаксическая ошибка: незакрытая двойная кавычка
```
